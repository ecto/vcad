# pcbeval — the ECAD model evaluation suite

Status: design draft, 2026-07-21. Sibling of mecheval; reuses its harness,
run-blob, pass^k, public/private split, and leaderboard machinery.

> **The AI designs the board AND we simulate, fab-check, and (eventually) build it.**

## Why ECAD is a different eval than MCAD

mecheval grades *geometry* — mass props, clearances, physics rollouts. A PCB is
graded on **connectivity + rules + electrical behavior**, and vcad already has
deterministic oracles for all three:

1. **Connectivity** — netlist↔copper reconciliation (`run_drc` NetIslands):
   is every declared net one copper island? No LLM judge needed; this is the
   ECAD analogue of `valid_solid`.
2. **Rules** — DRC (clearance, width, annular ring), ERC, DFM fab profiles,
   `validate_for_fab` as the single fail-closed gate.
3. **Behavior** — `simulate_circuit` (DC/AC), impedance/PDN/trace-current
   sizing calculators, thin-wire antenna MoM, thermal FV. "The LED actually
   lights" is computable.

The unique failure modes to grade against (things models actually get wrong):
footprint/pad mapping, decoupling-cap placement *proximity*, net-tie/split-net
topology, layer discipline, diff-pair symmetry, silkscreen-on-pad garbage,
current-carrying width, connector pinout mirroring.

## Suites

### Suite E — Schematic (netlist authoring)
Input: natural-language spec ("3.3V LDO regulator from 5V USB, with power LED").
Output: `create_schematic` netlist. Graded on:
- `erc_clean`
- `netlist_isomorphic` — graph isomorphism against a golden netlist (component
  types + pin-level connectivity, refdes-agnostic). Deterministic; ignore
  values within stated tolerance bands.
- `component_spec` — required part classes present (e.g. exactly one LDO,
  input+output caps ≥ specified capacitance).

### Suite P — Layout (the headline)
Input: a fixed netlist + board constraints (outline, stackup, design rules,
fab profile). Output: placed + routed board. Tiers:
- **P1 Placement** — components placed, no courtyard overlap, decoupling caps
  within N mm of their IC pin, connectors on stated edge. Route not required.
- **P2 Route simple** — ≤2 layer, all nets one island, DRC clean.
- **P3 Route constrained** — 4-layer with plane discipline, via stitching,
  current-carrying nets at computed width (`size_trace_for_current` oracle).
- **P4 High-speed** — diff pairs at target impedance (`size_impedance`),
  length matching within tolerance (`length_match_traces` as oracle),
  stub/via-count budgets.
- **P5 Full board** — spec → schematic → layout → `validate_for_fab` clean →
  Gerber export parses. End-to-end.

### Suite X — Cross-domain (vcad's moat)
Nobody else can grade these, because they need MCAD+ECAD in one kernel:
- board fits enclosure (`check_enclosure_fit`), connector apertures align
- mounting holes match host geometry (Fit-suite machinery reused)
- PCB motor: winding layout achieves target winding factor + `calc_motor`
  torque; `simulate_em` field check
- thermal: hot part + copper pour → `solve_thermal` max-temp ceiling
- antenna: trace antenna hits S11/frequency target (`analyze_antenna`)

### Suite K — Kernel (no AI)
Autorouter completion rate/track length vs corpus, DRC engine perf
(large-board scaling already has a benchmark), Gerber/KiCad round-trip
fidelity, footprint-engine IPC compliance.

## Check vocabulary (additions to SCHEMA.md)

```jsonc
{ "type": "erc_clean" }
{ "type": "drc_clean", "fab_profile": "jlc-2layer" }
{ "type": "validate_for_fab" }                       // the P-suite gate
{ "type": "netlist_isomorphic", "golden": "golden_netlist" }
{ "type": "nets_fully_connected" }                    // NetIslands == 1 per net
{ "type": "placement_proximity",                      // decoupling discipline
  "part_class": "decoupling_cap", "anchor": "ic_power_pin", "max_mm": 3.0 }
{ "type": "trace_current", "net": "VMOTOR", "amps": 3.0, "temp_rise_c": 10 }
{ "type": "impedance", "net_class": "usb_dp_dm", "ohms": 90, "tolerance_pct": 10 }
{ "type": "length_match", "net_class": "ddr_dq", "tolerance_mm": 0.5 }
{ "type": "circuit_behavior",                         // simulate_circuit oracle
  "analysis": "dc", "probe": "VOUT", "expect_v": 3.3, "tolerance_pct": 5 }
{ "type": "layer_budget", "max_layers": 2 }
{ "type": "board_envelope", "max_mm": [50, 50] }
{ "type": "gerber_roundtrip" }                        // export parses + matches copper
{ "type": "enclosure_fit", "host": "host_geometry", "min_clearance_mm": 0.5 }
{ "type": "thermal_ceiling", "power_map": "...", "max_temp_c": 85 }
```

## Anti-cheese, ECAD flavor

- `min_component_count` / required part classes — stops "one giant zone" boards
- `max_copper_area_pct` — stops flood-everything connectivity cheese
- `max_via_count`, `max_total_track_mm` — routing-quality ceilings
- `forbid_net_ties` unless the task grants them — stops shorting nets to
  fake connectivity (the NetIslands check plus ERC already catch most of this)
- golden netlist is grader-only (`agent_visible: false`), same as Fit hosts

## Scoring

Same as mecheval: all checks must pass, pass^k over k runs. Plus a
**quality score** for tie-breaking on passed P-suite tasks (routed length,
via count, unrouted ratsnest = hard fail): pass/fail decides the leaderboard,
quality orders within it. Never blend quality into pass — keeps the
deterministic-oracle philosophy intact.

## What makes this the *best* ECAD eval

1. **No LLM judge anywhere.** Every check is a kernel/solver computation.
   Competing ECAD evals (there are ~none serious) would have to shell out to
   KiCad scripting; vcad grades natively and fail-closed.
2. **Behavioral grading**, not just rule grading — `simulate_circuit` means a
   task can require the circuit to *work*, not merely be DRC-clean.
3. **Cross-domain suite X** is un-copyable without a unified kernel.
4. **Fab-real**: `validate_for_fab` + fab profiles mean a passing board is
   orderable; the mecheval "winning designs get manufactured" story carries
   over — winning boards get fabbed via the commerce path.
5. **Interop honesty**: KiCad import means tasks can also accept `.kicad_pcb`
   submissions, so the eval measures models, not vcad-API familiarity.
   (Phase 2 — grader ingests via `import_kicad`, same checks.)

## Build order

1. Extend `mecheval/tasks/SCHEMA.md` with the ECAD check vocabulary; add
   grader entry points that call the existing MCP/kernel oracles (the DRC/ERC
   checks are already stubbed in the schema — wire them for real).
2. E-tier + P1/P2 tasks (~15): golden netlists + fixed-netlist layout tasks.
   Villain baselines: "unrouted board", "flood zone board" — both must fail.
3. Harness: reuse mecheval's runner; solver emits a PCB session document
   (or `.kicad_pcb`) instead of `.vcad`. Exclude `verify_part`-style
   self-grading tools during scored runs, same policy as mecheval.
4. P3–P5 + X-tier; leaderboard section on the existing mecheval site.

Open question: separate `pcbeval/` tree vs a suite inside mecheval. Lean:
**suites inside mecheval** (E/P/X/K), branded "pcbeval" on the leaderboard —
one harness, one runs format, one submission spec; the cross-domain suite
literally needs both anyway.
